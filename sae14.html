SAÉ 1.04 : Création d'un site web dynamique

HTML5/CSS3 Développement Web UX Design Rugby Project

Contexte et travail demandé :

Dans ce projet, je devais concevoir un site web multipage en HTML/CSS. Le choix du thème étant libre, j'ai choisi de réaliser un site sur le rugby. Un cahier des charges nous était imposé :

Compétences visées :

  • Le site doit contenir au minimum trois pages : une page d'accueil présentant le contenu du site ; une page dédiée au sujet, riche en contenu ; une page « À propos » présentant l'auteur. D'autres pages optionnelles (contact, présentation des services) sont acceptées.
  • Le site doit avoir une charte graphique cohérente sur l'ensemble des pages.
  • Le site doit passer la validation W3C pour le HTML/CSS et être conforme à la norme WCAG 2.0 AA.
  • Flexbox ou CSS Grid doivent être utilisés pour la réalisation du site.
  • Le site doit s'adapter à tous types d'écrans (téléphone, tablette, ordinateur) grâce au design responsive.
  • Une ou plusieurs animations CSS doivent être présentes.
  • Le code source doit être déposé dans un dépôt GitHub et hébergé sur GitHub Pages.
  • Plusieurs commits doivent être réalisés et leur nommage doit être cohérent avec les modifications apportées au site.
  • Un README.md devra être réalisé et détaillé.

Réalisations techniques

Éléments clés du développement du site Rugby :

Interface & Mise en page responsive

Démonstration visuelle du site :

Mise en page : J'ai utilisé Flexbox pour aligner dynamiquement les éléments (images, scores de matchs, articles). Cette approche a permis une structure flexible et une adaptation fluide à différentes résolutions d'écran.

Responsive Design : Implémentation de media queries pour 5 points de rupture (1024px, 768px, 600px, 480px, 360px). Les éléments s'adaptent en hauteur et largeur pour garantir une lisibilité optimale sur tous les appareils.

Lien vers le site du projet : Voir le site en ligne

Validation W3C & Code Standards

Validation HTML/CSS : Le site a passé avec succès la validation W3C, garantissant un code sémantique et conforme aux standards actuels. Utilisation d'éléments <section>, <article>, <nav> et <footer> pour une structure logique.

Accessibilité (WCAG 2.0 AA) : Intégration d'attributs aria-label, contraste de couleurs respecté, navigation au clavier fonctionnelle, textes alternatifs sur les images.

Optimisations CSS : Utilisation de variables CSS, cascade correcte, absence de dépréciations. Minification et organisation modulaire du code.

Analyse Réflexive

Difficultés rencontrées & solutions apportées

1. Maîtrise du Responsive Design

Défi : Initialement, j'utilisais des marges et paddings fixes, ce qui provoquait des débordements et une mauvaise lisibilité sur petits écrans. Le positionnement d'éléments complexes (menu, cartes de joueurs, tableaux de scores) était rigide.

Solution adoptée : J'ai migré vers Flexbox et les unités relatives (%, vh, vw). Mise en place de 5 media queries stratégiques (1024px, 768px, 600px, 480px, 360px) permettant un redimensionnement fluide. Apprentissage de la propriété clamp() pour les espacements adaptatifs.

Résultat : Le site fonctionne maintenant sur tous les appareils sans décalages visuels.

2. Validation W3C & Standards du web

Défi : Respecter les normes W3C en HTML/CSS demandait une attention particulière à la sémantique, l'utilisation correcte des balises et l'absence de propriétés obsolètes.

Solution adoptée : Utilisation systématique d'éléments sémantiques (<header>, <nav>, <section>, <article>, <footer>). Vérification du code avec le validateur W3C à chaque étape. Intégration des critères d'accessibilité WCAG 2.0 AA (contraste de couleurs ≥ 4.5:1, attributs aria-label, navigation au clavier).

Résultat : Code validé W3C sans erreur ; site conforme aux standards d'accessibilité.
