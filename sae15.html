SAÉ 1.05 : Automatisation d'un flux de données

Python API REST JSON Automation

Contexte et Objectifs

Présentation générale

Réalisée au cours de l'année universitaire 2025-2026 au sein du département Réseaux et Télécommunications de l'IUT Grand Ouest Normandie (Campus de Caen/Ifs), la SAÉ 1.05 (Traiter des données) est un projet de développement logiciel complet encadré par M. Pépin et M. Brisacier.

Ce projet s'inscrit dans une problématique professionnelle concrète : un administrateur Réseaux & Télécoms doit régulièrement automatiser la collecte, le traitement et la mise en forme de données brutes issues de différents systèmes d'information (état d'un parc de machines, logs, données utilisateurs) afin de générer des synthèses exploitables.

L'objectif principal de cette SAÉ était de concevoir une suite d'outils en Python (version 3.11) permettant d'interagir avec des services distants via des API REST, de manipuler des structures de données complexes (JSON / XML), puis de générer automatiquement des rapports statistiques aux formats Markdown et HTML.

Travail demandé et livrables techniques

Le projet était articulé autour de trois grandes phases de développement, menées en autonomie par binôme :

1. Module de conversion universel (md_to_html.py)

  • • Implémentation d'une fonction logicielle convert s'appuyant sur la bibliothèque markdown pour transformer un fichier source .md en page web .html valide
  • • Conception d'une interface en ligne de commande (CLI) pour rendre le script exécutable directement depuis un terminal (avec l'utilisation bonus du module argparse pour la gestion des arguments)

2. Générateur de fiches de points d'intérêt (fiche_osm.py)

  • Collecte : Requêter l'API REST officielle d'OpenStreetMap (v0.6) afin de récupérer, au format JSON, l'ensemble des descripteurs bruts d'un nœud spécifique à partir de son identifiant (ex: le kebab Délices Magic Beau Gosse, nœud 5553036408)
  • Traitement & Export : Parser le dictionnaire Python obtenu pour structurer automatiquement les données utiles (nom, horaires, coordonnées, téléphone, site web) sous forme de fiches Markdown et HTML propres
  • Cartographie dynamique [Exclusivité Initiaux] : Intégration d'une fonction generate_map exploitant l'API Slippy Map. Le script devait calculer mathématiquement les coordonnées (x, y) d'une tuile cartographique selon un niveau de zoom donné, télécharger l'image correspondante, et utiliser la bibliothèque Pillow pour y superposer un marqueur visuel avant de l'injecter dans le rapport

3. Analyseur de zones géographiques et statistiques (infos_locales.py)

  • Extraction de masse : Utilisation de l'API Overpass et du langage de requêtage Overpass QL pour extraire massivement un ensemble d'objets spécifiques (ex: les restaurants et fast-foods) sur un secteur géographique délimité (Caen et Ifs)
  • Moteur statistique : Écriture d'algorithmes de tri et de calcul pour produire des indicateurs pertinents (ex: proportion d'établissements proposant de la vente à emporter, taux de remplissage des horaires d'ouverture sur OSM, part des pizzerias/kebabs, accessibilité PMR)
  • Restitution : Génération automatique d'un rapport de synthèse complet incluant les métadonnées techniques de la requête, les statistiques calculées et l'annuaire complet des lieux trouvés

    Réalisations techniques & Intégration des API

    Découverte et exploitation des interfaces de programmation (API) pour la collecte automatique de données géographiques :

    1. Requêtage Ciblé : API OpenStreetMap

    Principe : Utilisée dans fiche_osm.py, cette API permet d'interroger directement la base de données d'OpenStreetMap pour récupérer toutes les informations d'un point précis (nom, téléphone, horaires) à partir de son identifiant unique.

    def get_node(id: int) -> dict:
    url = f"https://www.openstreetmap.org/api/0.6/node/{id}.json"
    rep = requests.get(url)
    if rep.status_code == 200:
        return rep.json()['elements'][0]
    return None

    Explication du code : Le script construit l'adresse de requête en y insérant l'identifiant recherché. La fonction requests.get() interroge le serveur distant. Si le serveur répond positivement (code de succès 200), le résultat est directement extrait et converti en dictionnaire Python exploitable.

    2. Extraction de Masse : API Overpass

    Principe : Utilisée dans projet.py, l'API Overpass permet d'extraire massivement un ensemble de données sur toute une région en utilisant le langage de requête Overpass QL (ex: cibler toutes les bornes de recharge de Normandie).

    def get_dataset(query: str) -> dict:
    while True:
        try:
            reponse = requests.get(url, params={"data": query}, timeout=30)
            if reponse.status_code == 200:
                return reponse.json()
        except:
            pass
        time.sleep(2)

    Explication du code : L'extraction de masse pouvant surcharger le serveur ou couper à cause d'un timeout, j'ai mis en place une boucle de sécurité while True. Si la connexion échoue, le script intercepte l'erreur proprement, attend 2 secondes avec time.sleep(2), puis réessaye automatiquement jusqu'à récupérer les données.

    Preuves des difficultés rencontrées

    Documentation des tests et des blocages de requêtes lors de la liaison avec le serveur distant :

    ❌ Échec de liaison avec l'API (Avant)
    Python_API_Error 
    >>> import requests
>>> response = requests.get("https://api.openstreetmap.org/node/...")
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
! Erreur : Le serveur renvoie du HTML/XML brut au lieu du JSON attendu

    Situation : Mauvaise liaison de l'API dans le code. Le script n'envoyait pas le bon format de requête et plantait en essayant de lire la réponse du serveur.

    ✅ Requête API connectée et stable (Après)
    Python_API_Success 
    >>> url = "https://api.openstreetmap.org/api/0.6/node/5553036408.json"
>>> response = requests.get(url)
>>> print(response.status_code)
200
>>> data = response.json()  # Extraction reussie !

    Correction : Utilisation de l'URL correcte avec l'extension `.json` demandée par l'API et ajout de vérifications de sécurité dans le code Python.

    Analyse Réflexive

    Difficultés rencontrées & Solutions

    Lier et faire communiquer l'API avec notre code Python

    Le problème : Notre plus grosse difficulté a été de connecter proprement l'API OpenStreetMap avec notre code Python. Au début, nos requêtes n'aboutissaient pas ou le script plantait complètement en se bloquant. On a réalisé que l'API renvoyait par défaut des données brutes au format XML, alors que notre programme Python était configuré pour trier et lire des structures au format JSON. Le code n'arrivait pas à faire la liaison et générait des erreurs de décodage.

    Notre solution : Pour résoudre ce problème, nous avons utilisé la bibliothèque Python requests. Nous avons modifié l'URL de requêtage pour forcer l'API à nous envoyer directement du JSON (en ajoutant l'extension .json à la fin de l'identifiant du nœud). Ensuite, nous avons sécurisé la liaison en ajoutant un test de contrôle (if response.status_code == 200) pour vérifier que le serveur répond correctement avant de lancer l'extraction des données avec response.json().
